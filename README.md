# Matrix Sheets

Node.js CLI для переноса файлов через фотографии экрана. Создаёт PNG-листы с чёрно-белыми матрицами и восстанавливает файл из снимков. Работает локально после установки зависимостей.

Текст сохраняется побайтово: кириллица, латиница, символы вне BMP, BOM и переводы строк остаются без изменений. Формат содержимого не ограничен расширением `.txt`. Максимальный размер исходного файла — 32 MiB.

## Установка

Нужен Node.js 22 или новее. В каталоге проекта выполните:

```powershell
npm.cmd ci
node matrix-sheets.mjs --help
```

На Linux и macOS используйте `npm ci`. Создание листов и восстановление доступны на этих системах; встроенный полноэкранный просмотр предназначен для Windows.

Установка требует подключения к сети. Во время создания листов, просмотра и восстановления сетевые запросы не выполняются.

## Быстрый запуск

Сначала проверьте размер после сжатия и выбранную раскладку:

```powershell
node matrix-sheets.mjs inspect "input.txt"
```

Создайте ровно три листа размером 1920×1080 и откройте полноэкранный просмотр:

```powershell
node matrix-sheets.mjs pack "input.txt" --out "out" --pages 3 --cell auto --level Q --show
```

Размер ячейки выбирается максимально возможным для трёх листов, минимум — 2 пикселя. Если файл не помещается, команда завершится с ошибкой. Увеличьте число листов или разрешите автоматический выбор:

```powershell
node matrix-sheets.mjs pack "input.txt" --out "out-large" --pages auto --cell 3 --level Q --show
```

Снимите каждый лист телефоном и перенесите оригинальные фотографии в каталог `photos`. Затем восстановите файл:

```powershell
node matrix-sheets.mjs restore "photos" --out "restored.txt" --manifest "out/manifest.json"
```

Для восстановления нужны все части. Порядок фотографий не важен; повторные фотографии допустимы. При нехватке частей команда перечислит отсутствующие номера и не запишет файл. Каждая часть проверяется по CRC32, а собранный файл — по размеру и SHA-256.

Матрицы содержат двоичные части файла. Для восстановления используйте команду `restore`, сохранив фотографии; обычное приложение камеры не собирает файл автоматически.

## Команды

| Команда | Назначение |
|---|---|
| `inspect input.txt` | Сжать файл, показать размеры и раскладку без создания изображений |
| `pack input.txt --out out` | Создать `sheet-001.png`, последующие листы и `manifest.json` |
| `restore photos --out restored.txt` | Собрать файл из фотографий или готовых PNG |
| `show out` | Открыть готовые листы в полноэкранном окне Windows |
| `help` или `--help` | Показать краткую справку |

`pack` требует пустой каталог назначения. Команда `restore` принимает несколько файлов и каталогов; каталоги просматриваются без вложенных папок. Поддерживаются PNG, JPEG, WebP, TIFF и BMP.

## Аргументы

| Аргумент | Значение по умолчанию | Назначение |
|---|---|---|
| `--out PATH` | `out` для `pack` | Каталог листов или имя восстановленного файла; обязательно для `restore` |
| `--pages N\|auto` | `3` | Точное число непустых листов, от 1 до 1000; `auto` выбирает минимальное число для заданного размера ячейки |
| `--cell N\|auto` | `auto` | Целое число пикселей на ячейку; `auto` выбирает максимальный размер от 2 пикселей |
| `--level L\|M\|Q\|H` | `Q` | Уровень восстановления повреждённых элементов: L — самая высокая вместимость, H — самая большая избыточность |
| `--width N` | `1920` | Ширина листа в пикселях, от 128 до 8192 |
| `--height N` | `1080` | Высота листа в пикселях, от 128 до 8192 |
| `--version N\|auto` | `auto` | Размер матрицы, от 1 до 40; обычно оставляйте автоматический выбор |
| `--compression auto\|none\|gzip\|brotli` | `auto` | Выбор сжатия; `auto` сравнивает исходные байты, gzip уровня 9 и Brotli качества 11 |
| `--show` | Выключено | После `pack` открыть просмотр в Windows |
| `--monitor N` | `0` | Номер монитора для просмотра, начиная с нуля; нужен для `show` или `pack --show` |
| `--seconds N` | `0` | Интервал автоматического переключения листов в секундах; `0` — ручной просмотр |
| `--manifest PATH` | Не задан | Путь к `manifest.json` для дополнительного поиска частей в отдельных областях листа |
| `--corners PATH` | Не задан | JSON с четырьмя углами экрана для каждой фотографии; требует `--manifest` |
| `--scan-width N` | `3072` | Максимальная длина большей стороны фотографии при поиске частей; `0` оставляет исходное разрешение, остальные значения — от 256 до 8192; применяется при `restore` |
| `--transfer HEX` | Не задан | Выбор одной передачи по 32-значному идентификатору, если снимки содержат несколько разных файлов |
| `--force` | Выключено | Разрешить замену существующего файла при `restore` |

Если используются одновременно `--pages auto` и `--cell auto`, приоритетом будет минимальное число листов. Для фотографирования удобнее явно задавать `--cell 3` или `--cell 4`.

`--cell 1` доступен только при явном указании. Для фотографии монитора этот размер не рекомендуется. Повышение уровня с Q до H уменьшает вместимость и может потребовать дополнительных листов; оно не устраняет расфокусировку, блики или муар.

Фотографии высокого разрешения автоматически уменьшаются перед поиском частей. Для крупных снимков выполняется дополнительный проход при размере большей стороны в две трети от `--scan-width`: с настройкой по умолчанию это 3072 и 2048 пикселей. Это помогает при муаре. Изображения меньшего размера не увеличиваются. Если заданы углы, сначала исправляется перспектива в исходном разрешении фотографии.

## Рекомендации до 300 000 символов

Число символов даёт только ориентир. Основной показатель — `packageBytes` в выводе `inspect`: размер сжатого содержимого вместе со служебными данными. Повторяющийся текст сжимается значительно лучше случайных строк. Кириллица и латиница занимают разный объём в исходном файле.

Для экрана 1920×1080 начинайте с таких параметров:

| Объём текста | Рекомендуемые параметры | Цель |
|---|---|---|
| До 10 000 символов | `--pages 1 --cell auto --level Q` | Один лист с максимально крупными ячейками; при нехватке места используйте следующий профиль |
| 10 000–50 000 | `--pages auto --cell 4 --level Q` | Крупные ячейки для первых пробных фотографий |
| 50 000–150 000 | `--pages auto --cell 3 --level Q` | Практичный баланс размера ячейки и числа снимков |
| 150 000–300 000 | `--pages auto --cell 3 --level Q` | То же качество изображения, число листов определяется фактическим сжатием |
| Любой объём, нужно ровно 3 листа | `--pages 3 --cell auto --level Q` | Максимально крупные ячейки в пределах трёх листов; слишком большой файл будет отклонён |
| Нужно уменьшить число снимков | `--pages auto --cell 2 --level Q` | Более плотные листы; сначала проверьте один снимок на своём экране и телефоне |
| Есть проблемы с фокусом или муаром | `--pages auto --cell 4 --level Q` | Больше листов и крупнее ячейки |

Максимальная расчётная вместимость одного листа 1920×1080 при уровне Q:

| Размер ячейки | Полезная вместимость листа | Ориентир для трёх листов |
|---|---:|---:|
| 2 пикселя | 22 005 байт | 66 015 байт |
| 3 пикселя | 8 802 байта | 26 406 байт |
| 4 пикселя | 4 638 байт | 13 914 байт |

Значения относятся ко всему пакету, включая имя и служебные данные. Автоматическая раскладка может выбрать другой размер матрицы с меньшим числом частей, если он укладывается в заданное число листов. Точную раскладку всегда показывает `inspect`.

Пример измерений на тестовом тексте с кириллицей, латиницей, переводами строк и уникальными шестнадцатеричными значениями:

| Символов | Исходных байт | После сжатия, байт | Листов при 2 px | При 3 px | При 4 px |
|---:|---:|---:|---:|---:|---:|
| 10 000 | 12 662 | 2 554 | 1 | 1 | 1 |
| 50 000 | 62 999 | 11 969 | 1 | 2 | 3 |
| 150 000 | 188 788 | 35 347 | 2 | 4 | 8 |
| 300 000 | 377 041 | 69 845 | 4 | 8 | 16 |

Это результаты конкретного содержимого, а не обещание для любого текста такого размера. Для плохо сжимаемого файла из 300 000 символов число листов может быть существенно больше.

Для сравнения нескольких вариантов без создания изображений:

```powershell
node matrix-sheets.mjs inspect "input.txt" --pages auto --cell 2 --level Q
node matrix-sheets.mjs inspect "input.txt" --pages auto --cell 3 --level Q
node matrix-sheets.mjs inspect "input.txt" --pages auto --cell 4 --level Q
```

## Просмотр и фотографирование

```powershell
node matrix-sheets.mjs show "out" --monitor 0
node matrix-sheets.mjs show "out" --monitor 0 --seconds 10
```

Стрелка вправо, пробел или PageDown — следующий лист; стрелка влево или PageUp — предыдущий; Esc — закрыть окно. Листы показываются в масштабе 1:1 по центру монитора. Если лист больше монитора, просмотр завершится с ошибкой. Для нескольких мониторов при необходимости выберите другой `--monitor`.

Для Samsung S25 и экрана 1920×1080 начните с ячейки 3 пикселя. Держите телефон примерно параллельно экрану, включите обычный режим фото без цифрового увеличения, наведите фокус на матрицы и оставьте все четыре угла экрана в кадре. Сохраните оригинальные фотографии без уменьшения и пересылки с потерей качества. Каждый лист лучше снять дважды, если уверенность в первом снимке низкая.

При смене разрешения монитора задайте соответствующие `--width` и `--height`. Снимок всего экрана удобнее обрабатывать, если экран занимает большую часть кадра. Если изображение наклонено, используйте углы, описанные ниже.

Три листа увеличивают возможный размер ячеек по сравнению с одним листом, но сами по себе не гарантируют чтение. Потерянный лист не восстанавливается из остальных. Успех подтверждается сообщением `verified: true` после сборки файла.

Проверено на трёх реальных фотографиях Samsung Galaxy S25 размером 8160×4592. Листы 1920×1080 с ячейкой 2 пикселя и уровнем Q содержали 26 частей, распределённых как 8 + 9 + 9. Файл размером 180 947 байт, примерно 163 000 символов, восстановился с полным совпадением SHA-256. Настройки поиска были стандартными; ручное задание углов не потребовалось. Это подтверждение для этих снимков и условий съёмки, а не гарантия для любого монитора или положения телефона.

## Исправление перспективы

Создайте JSON-файл с координатами углов видимой области экрана на каждой фотографии. Порядок: верхний левый, верхний правый, нижний правый, нижний левый. Координаты измеряются в пикселях после применения ориентации фотографии; начало — верхний левый угол изображения.

```json
{
  "photo-1.jpg": [[120,90],[2450,130],[2410,1440],[100,1400]],
  "photo-2.jpg": [[118,94],[2455,128],[2418,1445],[104,1404]]
}
```

```powershell
node matrix-sheets.mjs restore "photos" --out "restored.txt" --manifest "out/manifest.json" --corners "corners.json"
```

Используйте реальные координаты своих снимков. Имя ключа должно совпадать с именем фотографии. Для фотографии без записи в JSON команда выполнит обычный поиск без исправления перспективы.

Если частей не хватает, добавьте более чёткие снимки в тот же каталог и повторите команду. Для дополнительных попыток можно фотографировать отдельные матрицы крупнее: порядок и наличие повторных частей не мешают сборке.

## Проверка результата

Успешная команда завершает процесс со статусом 0, ошибка — со статусом 1. Итоговые размеры, параметры и SHA-256 выводятся в JSON в стандартный поток вывода; ход работы и сообщения об ошибках — в стандартный поток ошибок.

Можно дополнительно сравнить исходный и восстановленный файлы в PowerShell:

```powershell
Get-FileHash "input.txt" -Algorithm SHA256
Get-FileHash "restored.txt" -Algorithm SHA256
```

Сжатие и контрольные суммы не скрывают содержимое. Фотографии позволяют восстановить исходный файл.
