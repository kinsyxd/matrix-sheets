# Matrix Sheets 2.3.0

Node.js CLI для переноса файлов через фотографии экрана. Создаёт PNG-листы с QR-матрицами и восстанавливает исходный файл из снимков. Создание листов работает одним `matrix-sheets.mjs` на Node.js 22 или новее, используя только встроенные модули. npm, компилятор, Python и права администратора для создания листов не нужны.

Файл сохраняется побайтово: кириллица, латиница, символы вне BMP, BOM и переводы строк не изменяются. Расширение файла не ограничено `.txt`; предел исходного файла — 32 MiB. Сжатие и контрольные суммы не скрывают содержимое.

Обновление существующей установки из ZIP описано в [UPDATE-CORPORATE.md](UPDATE-CORPORATE.md).

## Быстрый запуск

```powershell
node matrix-sheets.mjs version
node matrix-sheets.mjs inspect "input.txt" --compare
node matrix-sheets.mjs pack "input.txt" --out "out"
```

Стандартный режим использует чёрно-белые матрицы, уровень коррекции Q и автоматическую раскладку: сначала минимальное число листов, затем максимально крупная ячейка от 2 пикселей, затем минимальное число частей. Выбор зависит от фактического размера пакета после сжатия; прежних профилей по числу символов больше нет. `inspect` показывает рассчитанные параметры без создания PNG, а `--compare` сравнивает доступные режимы на том же файле. Если ограничения не позволяют выбранный режим, сравнение всё равно возвращает результат по каждому режиму: допустимую раскладку либо `feasible: false` с причиной ошибки.

Для ровно трёх непустых листов:

```powershell
node matrix-sheets.mjs pack "input.txt" --out "out-three" --pages 3
```

Если файл не помещается в заданное число листов, команда завершается с ошибкой. При автоматическом числе листов они заполняются последовательно; свободные места на последнем листе допустимы. Число листов не ограничено тремя автоматически.

Для более крупных ячеек при фотографировании:

```powershell
node matrix-sheets.mjs pack "input.txt" --out "out-large" --cell 4 --level Q
```

`pack` требует пустой каталог назначения. Откройте PNG вручную в разрешённом просмотрщике, выставьте масштаб 100% и сфотографируйте каждый лист. После установки зависимостей восстановите файл:

```powershell
node matrix-sheets.mjs restore "photos" --out "restored.txt" --manifest "out/manifest.json"
```

Нужны все части; порядок и повторные снимки не мешают сборке. Каждая часть проверяется по CRC32, собранный файл — по размеру и SHA-256. До успешной проверки итоговый файл не записывается. Успех подтверждается `verified: true`. Обычное приложение камеры само файл не собирает.

## Короткая команда в Git Bash

Откройте Git Bash в каталоге установки:

```bash
source ./terminal.bash
msheets version
msheets inspect "input.txt" --compare
msheets pack "input.txt" --out "out"
```

Функция `msheets` вызывает `node "$MATRIX_SHEETS_ENTRY"` и передаёт аргументы без изменений. Она работает из любого каталога в текущем сеансе; относительные пути к данным считаются от текущего каталога терминала. Подключение не меняет PATH или профиль пользователя. При обновлении файлов в том же каталоге существующая функция продолжает указывать на тот же `.mjs`.

Текущий путь можно проверить в Git Bash:

```bash
printf '%s\n' "$MATRIX_SHEETS_ENTRY"
type msheets
```

## Зависимости для восстановления

Для `inspect`, `pack`, `show`, `version` и `help` достаточно одного `.mjs`. Только `restore` требует прежние зависимости: `sharp` **0.35.5** и `zxing-wasm` **3.1.5**. В каталоге установки выполните:

```powershell
npm.cmd ci --ignore-scripts --no-audit --no-fund
```

В Git Bash, Linux или macOS используйте `npm ci --ignore-scripts --no-audit --no-fund`. Используются готовые платформенные библиотеки, без компиляции на поддерживаемой платформе. Установка загружает пакеты из npm; рабочие команды не выполняют сетевых запросов. Восстановление загружает локальную нативную библиотеку обработки изображений и WebAssembly-модуль.

При обновлении 2.2.0 → 2.3.0 с теми же установленными зависимостями переустановка не нужна. Не удаляйте существующий `node_modules`.

## Режимы и экспериментальная плотность

| Режим | Параметры по умолчанию | Применение |
|---|---|---|
| `--preset standard` | Чёрно-белый, Q, автоматическая ячейка от 2 px | Основной режим |
| `--preset dense-experimental` | Чёрно-белый, L, 2 px | Больше данных на листе ценой меньшей избыточности |
| `--preset color-experimental` | Цветные слои QR, ячейка от 3 px | Экспериментальная передача через 4 или 8 цветов |

Явные `--cell`, `--level` и `--pages` переопределяют соответствующие настройки режима. Цветной режим автоматически сравнивает 2 и 3 независимых слоя QR. Порядок выбора: меньше листов, затем крупнее ячейки, затем меньше цветов/слоёв, затем меньше частей. Число слоёв можно закрепить через `--layers 2` или `--layers 3` (только для цветного режима). Каждый слой несёт части того же проверяемого пакета. Явная цветная ячейка `--cell 2` допустима как экспериментальная настройка.

```powershell
node matrix-sheets.mjs inspect "input.txt" --compare
node matrix-sheets.mjs pack "input.txt" --out "out-dense" --preset dense-experimental
node matrix-sheets.mjs pack "input.txt" --out "out-color" --preset color-experimental --layers 3
node matrix-sheets.mjs restore "out-color" --out "restored-color.txt" --manifest "out-color/manifest.json"
```

Плотный и цветной режимы требуют проверки на своём экране и телефоне. Восстановление исходных цветных PNG проверяет кодирование, но не подтверждает надёжность реальной фотографии. Успех цветного режима на физической камере пока не подтверждён. В синтетических JPEG часть слоёв при 2 px не читалась; 3 px дали успешный результат в проверенных условиях. Это не гарантия для другого экрана, камеры или качества JPEG. Уменьшение числа листов зависит от файла и настроек; фиксированного выигрыша в 4 или 10 раз нет.

## Команды и параметры

| Команда | Назначение |
|---|---|
| `version` | Показать версию приложения и путь запускаемого `.mjs` |
| `inspect FILE [--compare]` | Показать сжатие и раскладку; при `--compare` сравнить режимы |
| `pack FILE --out DIR` | Создать `sheet-001.png`, следующие листы и `manifest.json` |
| `restore FILE_OR_DIR... --out FILE` | Собрать файл из фотографий или готовых PNG |
| `show DIR` | Вывести абсолютные пути PNG для ручного открытия |
| `help` или `--help` | Показать справку |

| Аргумент | Значение по умолчанию | Назначение |
|---|---|---|
| `--preset standard\|dense-experimental\|color-experimental` | `standard` | Режим создания листов |
| `--layers 2\|3` | Автоматический выбор 2 или 3 | Число слоёв в цветном режиме |
| `--out PATH` | `out` для `pack` | Каталог листов или восстановленный файл; обязателен для `restore` |
| `--pages N\|auto` | `auto` | Точное число непустых листов от 1 до 1000 или автоматический расчёт |
| `--cell N\|auto` | Зависит от режима | Целое число пикселей на ячейку или автоматический выбор |
| `--level L\|M\|Q\|H` | Q; L в dense | Уровень коррекции QR: L даёт больше вместимости, H — больше избыточности |
| `--width N`, `--height N` | `1920`, `1080` | Размер листа: от 128 до 8192 пикселей по каждой стороне |
| `--version N\|auto` | `auto` | Версия **QR** от 1 до 40; это не версия приложения |
| `--compression auto\|none\|gzip\|brotli` | `auto` | `auto` сравнивает исходные байты, gzip уровня 9 и Brotli качества 11 |
| `--show` | Выключено | После `pack` вывести пути PNG |
| `--manifest PATH` | Не задан | Манифест для поиска частей по областям листа и метаданных режима |
| `--corners PATH` | Не задан | Углы экрана для исправления перспективы; требует `--manifest` |
| `--scan-width N` | `3072` | Наибольшая сторона фотографии для поиска: `0` — оригинал, иначе 256–8192 |
| `--transfer HEX` | Не задан | Выбрать передачу по 32-значному идентификатору при нескольких файлах на снимках |
| `--force` | Выключено | Разрешить замену существующего результата `restore` |

Автоматический выбор ячейки начинается с 2 px в чёрно-белом режиме и с 3 px в цветном. Для чёрно-белого режима `--cell 1` доступен только явно и не рекомендуется для фотографирования. Более высокий уровень коррекции не устраняет блики, расфокусировку и муар. Точную раскладку и параметры выбранного режима проверяйте через `inspect`.

Восстановление автоматически распознаёт чёрно-белую и цветную передачу; прежние чёрно-белые листы и манифесты остаются совместимыми. Каталоги фотографий просматриваются без вложенных папок. Поддерживаются PNG, JPEG, WebP, TIFF и BMP.

## Просмотр и фотографирование

`show` выводит пути и не запускает просмотрщик. Откройте лист вручную в разрешённом приложении, включите полный экран и масштаб 100%: это разные настройки. Изображение должно помещаться на монитор целиком. Нижняя полоса содержит номер листа и учитывается при раскладке: 32 px в чёрно-белом режиме и 64 px в цветном, где также размещены цветовые метки.

Начните с чёрно-белого режима и ячейки 3–4 px. Держите телефон примерно параллельно экрану, используйте обычный режим фото без цифрового увеличения, наведите фокус на матрицы и оставьте четыре угла экрана в кадре. Сохраняйте оригиналы без уменьшения и пересылки с потерей качества. При смене разрешения монитора задайте соответствующие `--width` и `--height`.

Крупные фотографии уменьшаются перед поиском; выполняется дополнительный проход в двух третях от `--scan-width`. Небольшие изображения не увеличиваются. Если заданы углы, перспектива исправляется в исходном разрешении фотографии.

## Исправление перспективы

JSON содержит углы видимой области экрана в порядке: верхний левый, верхний правый, нижний правый, нижний левый. Координаты измеряются после применения ориентации фотографии, от верхнего левого угла изображения.

```json
{
  "photo-1.jpg": [[120,90],[2450,130],[2410,1440],[100,1400]]
}
```

```powershell
node matrix-sheets.mjs restore "photos" --out "restored.txt" --manifest "out/manifest.json" --corners "corners.json"
```

Используйте свои координаты и точные имена фотографий. Для снимка без записи в JSON выполняется обычный поиск. Если частей не хватает, добавьте более чёткие снимки или снимите отдельные матрицы крупнее и повторите команду.

## Проверка и локальная политика

Успех завершает процесс со статусом 0, ошибка — со статусом 1. Результат выводится в JSON в stdout, сообщения о ходе работы и ошибках — в stderr. Размеры и SHA-256 относятся к исходным байтам; подсчёт символов носит информационный характер и не выбирает режим. Для дополнительной проверки:

```powershell
Get-FileHash "input.txt" -Algorithm SHA256
Get-FileHash "restored.txt" -Algorithm SHA256
```

Утилита не запускает дочерние процессы и не меняет защиту, реестр, сеть, службы или политики выполнения приложений. Создание листов не загружает нативные дополнения или WebAssembly. Выбирайте разрешённые каталоги для чтения и записи. Если Node.js, npm или компоненты восстановления заблокированы корпоративной политикой, используйте штатный процесс согласования.

Для создания листов можно перенести только `.mjs`. Для автономного восстановления подготовьте зависимости указанной командой на разрешённом компьютере с той же ОС и архитектурой и перенесите каталог вместе с `node_modules` разрешённым способом. Совместимость зависит от конкретной политики и поддерживаемой платформы.
